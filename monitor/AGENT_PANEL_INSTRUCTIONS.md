# coco 面板维护规则

你通过 coco 启动，用户正在右侧观察本次工作的日志。下面的当前窗口信息适用于本次启动；恢复旧会话后使用本次槽位和路径，不要沿用历史会话里的槽位。

- GPU 和 Codex 账号用量由程序自动刷新，无需你维护。右下日志面板需要你绑定真实任务日志；没有任务面板，不必调用 set-task。
- 开始长任务、评测、训练、构建或后台程序前，在项目约定的日志目录创建本次任务专用日志。使用唯一文件名，`touch "$job_log"` 后执行下方绑定命令。程序的标准输出和错误输出均写入该日志；Python 任务优先使用 `python -u` 避免缓冲。
- `COCO_LOG_PATH` 是面板的入口链接，不是新任务日志文件。不要截断它、把它当新日志路径，或直接往它所指向的旧任务日志写新任务输出。
- 日志应反映真实进度：开始时记录任务名称与时间；关键阶段记录状态；结束时根据实际退出码追加 DONE 或 FAILED、时间和结果路径。启动成功不等于任务完成，不得伪造进度、把失败标为成功。
- 切换任务时绑定新日志。完成后保留日志与当前绑定供用户查看；无需为普通问答和短小只读操作创建日志。
- 同时有多个后台任务时，把面板绑定到主任务或汇总日志，并告知用户正在展示哪个任务。日志中不要写入密钥或令牌。
- 只维护当前窗口的槽位。不改其他槽位、关闭其他会话或清理其他进程。自建进度 watcher 应随对应任务 PID 退出。
- 刚启动时等待用户任务，不要仅因为加载这些规则就启动实验、清理文件或创建后台任务。

## 绑定日志示例

`job_log` 必须是当前任务的真实日志路径。先创建文件，再使用启动时给出的绑定命令，例如：

```bash
touch "$job_log"
<当前窗口的绑定命令> "$job_log"
```
